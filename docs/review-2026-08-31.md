## Benchmark adequacy and selection

The catalog must distinguish a model, a provider route and an evaluated system.
The following changes prevent misleading rankings; they do not certify the
methodology of every upstream benchmark.

- Comparison lanes now include evidence source as well as metric, unit,
  variant, effort, evaluator, dataset version and configuration. Previously
  saved lane IDs must be rediscovered. Unknown protocol details are still
  unknown, even within one aggregator.
- Score direction is explicit or resolved only from known metrics. WER and
  Brier score are minimized; Brier Index is maximized. Generic `score` requires
  an explicit direction. API sorting and offline scoring share the same code.
  [ForecastBench's leaderboard](https://www.forecastbench.org/leaderboards/)
  distinguishes its index from raw Brier score.
- Claim and aggregate observations cannot enter scoring through row ordering.
  Null, strings and booleans are missing evidence, not measured zeroes.
  Weights, coverage penalties, cohort sizes, published sample counts and
  uncertainty remain visible. Confidence is a heuristic, not a statistical
  interval or a probability of success. Percentiles depend on cohort membership.
- Arena preserves product names such as Qwen Max, Flux Max and Codex Max while
  extracting supported effort suffixes for evaluated GPT, Claude, Grok,
  Gemini, GLM and Kimi configurations.
- LiveBench task/category costs and output-token statistics use their own
  question counts and original column names; category and overall aggregates
  are not extra independent task votes. [Upstream aggregation code](https://github.com/LiveBench/new-livebench/blob/main/src/lib/compute.js).
- Vals VoiceCodeBench's task success, canonical-token entity match and WER
  retain distinct metrics rather than becoming generic accuracy.
  [VoiceCodeBench](https://www.vals.ai/benchmarks/voice-code-bench).
- Open ASR does not imply an H200 environment for rows without published
  hardware. RTFx is not provider latency, and speech TTFS/TTFA are not TTFT.
  [Open ASR repository](https://github.com/huggingface/open_asr_leaderboard).
- Quality/cost Pareto ranking excludes unknown or incompatible workload limits,
  incomplete cost, and non-exact effort/quantization transfer. An uncertain
  cheap route cannot dominate a verified one. Equivalent points retain model
  identity and evidence. Speed objectives require matching scope, window,
  percentile and observation.
- The business playbook now distinguishes [GDPval-AA v2](https://artificialanalysis.ai/evaluations/gdpval-aa/)
  from original GDPval: Stirrup, pairwise judging and Elo are not a percentage
  of professional reliability. Published fallback/scaffold conditions must
  accompany a system score; unversioned catalog rows cannot be called current v2.

## Workload economics

The API and selector share one estimator. Total input is partitioned into
ordinary input, cache reads and cache writes; reads plus writes cannot exceed
the prompt. Explicit cache-write billing distinguishes replacement rates
(Claude) from additional storage charges (Gemini on OpenRouter). Unknown
billing semantics remain unknown. See [Claude cache pricing](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
and [OpenRouter cache semantics](https://openrouter.ai/docs/guides/best-practices/prompt-caching).

OpenRouter context thresholds are strict greater-than, and the last matching
override wins per price key. Normalized ranges are disjoint; unconditional
later overrides also shadow earlier scheduled prices for the affected key.
Returned rates already include discounts. Explicit Models.dev ranges preserve
both bounds. Conflicting bounded tiers, unsupported volume pricing and
unresolved time-dependent prices remain unknown. Negative price sentinels are
not credits. [OpenRouter's override contract](https://github.com/OpenRouterTeam/terraform-provider-openrouter/blob/main/docs/data-sources/model.md).

Token and request counts must be safe integers; ratios and totals must be
finite. Workload compatibility is returned alongside API cost estimates.
Budget filters require proven compatibility. Cost caching is keyed by the
actual indexed offer, not an offer ID that may occur under another model.

## API, artifacts and deployment

- Available summaries, provider counts, facets, context sorting and exclusion
  counts use the same eligible offers. Combined constraints must hold on one
  offer. Malformed counts/enums/IDs produce HTTP 400; errors are not cached,
  and HTTP 500 does not expose internal exception text.
- Nested schema validation and recomputed content hashes protect archives,
  runtime files and downloads. Orphan observations and incorrect lane IDs are
  rejected rather than silently dropped. Dates, schedules, measurements,
  prices, reasoning and source projections receive field checks.
- Atomic snapshot writes use unique temporary files and fsync. Downloaded
  bundles use immutable generation directories and an atomic manifest;
  concurrent readers cannot mix generations. Cached bytes are revalidated,
  and corrupt-cache recovery is visible. Old generations require explicit
  cleanup when no reader needs them.
- Tests build current artifacts first. CI covers push/PR changes, including
  shared production modules inside `.agents`. Node 24 is explicit. A real
  draft-2020-12 validator checks the published schema against the full snapshot;
  archive/runtime/static queries and health must agree.
  Generated runtime/static copies are excluded from CLI source uploads and
  recreated by the deployment build, avoiding duplicate archive uploads.
- The landing page no longer displays invented fallback counts after a failed
  health request. It exposes the snapshot time and source warnings/unavailability.
  Its script was checked without opening or automating a browser.
- Automated publication checks retained Artificial Analysis evidence,
  derivatives and evaluator provenance before push/Pages and Vercel builds.
  Redistribution rights were not established during this review. Local builds
  remain available. This is an automation guard, not protection for existing
  public Git history, manual pushes or already-deployed files.
  [Artificial Analysis Data API terms](https://artificialanalysis.ai/data-api).

No credentials or `.env` files were loaded for the public refresh, no models
were run, and no provider credits were spent. No public push or deployment was
performed. The redistribution confirmation flag was not enabled.

## Validation and performance

`npm run check` passes type checking, rebuilds the artifacts, and runs the
deterministic suite: **137 passed, zero failed, 15 opt-in network tests skipped**.
The separate public-source contract run passed **11 tests**, skipping only the
two AA tests that require a key. Dependency audit reported zero vulnerabilities.
The publication preflight was verified to reject this snapshot without license
confirmation. The data audit records these totals and seven zero-anomaly checks.

The [benchmark harness](../scripts/benchmark.ts) replaces unsupported historical
JSON/NDJSON/SQLite comparisons. It reports process-cold load plus validation,
index build, first request, warm p50/p95, serialization, response sizes and RSS
in isolated processes. The [recorded run](review-2026-08-31-benchmark.json)
includes versions, hardware, snapshot hash and file sizes. It is not a
serverless/CDN benchmark, and the operating-system page cache is uncontrolled.
No timing threshold is imposed in CI.

One run on Node 24.18.0 / Apple M3 Pro, 100 warm samples per case:

| Measurement | Archive input | Runtime input |
| --- | ---: | ---: |
| File size | 90.41 MB pretty / 52.22 MB minified | 54.82 MB |
| Load and validate, one cold process | 1,116 ms | 978 ms |
| Build query index | 191 ms | 181 ms |

| Costed-offer query p50 / p95 | 45.45 / 56.43 ms | 43.81 / 50.64 ms |

the peak across loading and repeated queries, not the retained snapshot size.

size with headroom under the [4.5 MB function response limit](https://vercel.com/docs/functions/limitations).

## Remaining limits

Public evidence is incomplete and some feeds are HTML/CSV contracts without a
versioned API. Future upstream changes should fail visibly, but passing the
current contract does not guarantee future compatibility. Key-gated AA data
was retained, not refreshed. Benchmark-specific judges, scaffolds, contamination,
hardware, sample distributions and fallback models may be unpublished; do not
infer statistical significance or universal model quality from the catalog.

Availability reflects fresh published metadata at snapshot generation time,
not successful paid inference. Named cache profiles are assumptions. Scheduled
or non-text workload dimensions outside the estimator remain unresolved.
The full snapshot and runtime require meaningful cold-start memory and file
space; consult the measured run and deployment limits before publishing.
Vercel packaging is configured but a live deployment was not exercised.
